Scope, budgets and known limits

The model imports the game's actual structure wall stamp and decorative shell functions verbatim. It starts with empty terrain: random terrain, cave carving, enemies, loot, interaction props and terrain elevation transitions are deliberately absent. Geometry is baked once; internal cell faces are removed and adjacent coplanar faces merged. Exposed steps between unequal wall heights are retained. This is a model adapter prototype, not a replacement game renderer.

The same 2,048-primitive baseline remains available, with explicit 4,096/8,192 comparisons and a 256-triangle per-face cap. These are work limits, not maximum object dimensions. Capped faces and solid fallbacks are reported, never counted as full-quality texturing. Directional strips can issue four pattern fills each, versus two per triangle: equal primitive counts do not mean equal cost. This option stays off by default pending performance and browser readback-path compatibility work. Distant brick detail becomes a filtered average at this resolution.

The motion test reports the candidate and triangle comparison separately. Retained triangle failures still appear in the overall report; a passing candidate group does not erase them. The small-object study additionally checks both browser context preferences; readback-optimized captures currently expose color rounding beyond their original one-byte tolerance.

Benchmark: 20 warm-up and 90 measured frames per phase, A/B/B/A, selected structure and viewpoint, identical repeatable camera motion. Controls lock and offscreen/hidden runs abort. Reports include projection, pixel-depth and mapping stages, actual fills and declined mapping attempts, plus 60/120 Hz submission overruns. The 18 native visibility checks cover both mapping paths, using independent ray/triangle intersections, actual texture pixels and an omitted-body negative control. These do not certify all viewpoints, collision or low-end performance.
